# Portfolio Backend + Admin Panel (TypeScript)

A small Express + MongoDB API, written in TypeScript, that stores everything
on your portfolio (profile, education, skills, experience, projects,
certifications, achievements), plus a password-protected admin panel at
`/admin` to edit it all without touching code.

## Structure

```
src/                    TypeScript source — edit this
  server.ts
  seed.ts
  config/db.ts
  middleware/auth.ts
  models/                 one Mongoose model per resource
  routes/                  one router per resource + a generic CRUD factory
dist/                    compiled JS output (generated by `npm run build`, don't edit)
admin/
  admin.ts                admin panel TypeScript source — edit this
  admin.js                 compiled output (generated, don't edit)
  admin.css, index.html
tsconfig.json            compiles src/ -> dist/
admin/tsconfig.json      compiles admin.ts -> admin.js (browser target)
```

## 1. Set up MongoDB Atlas (free tier)

1. Go to https://www.mongodb.com/cloud/atlas/register and create a free account.
2. Create a free M0 cluster.
3. Under **Database Access**, add a database user with a username/password.
4. Under **Network Access**, add `0.0.0.0/0` (allow from anywhere) — simplest for
   a small personal project. Render's IPs change, so this avoids connection issues.
5. Click **Connect > Drivers**, copy the connection string. It looks like:
   `mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/`
6. Add `/portfolio` before the `?` so it points at a database named `portfolio`:
   `mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/portfolio?retryWrites=true&w=majority`

## 2. Configure environment variables

Copy `.env.example` to `.env` and fill in:

- `MONGODB_URI` — the connection string from step 1
- `JWT_SECRET` — any long random string (e.g. run `openssl rand -hex 32`)
- `CORS_ORIGIN` — your live portfolio URL(s), comma-separated
- `ADMIN_USERNAME` / `ADMIN_PASSWORD` — your admin login (used once by the seed script)
- `CLOUDINARY_CLOUD_NAME` / `CLOUDINARY_API_KEY` / `CLOUDINARY_API_SECRET` — for file
  uploads (certificates, project images) from the admin panel. Sign up free at
  https://cloudinary.com/users/register/free, then copy these three values from
  your dashboard homepage.

## 3. Install, build, seed, and run locally

```bash
npm install
npm run seed         # creates your admin login + fills the DB with your current content
npm run dev            # runs src/server.ts directly with hot-reload (ts-node-dev)
```

For a production-style run:

```bash
npm run build         # compiles src/ -> dist/
npm start               # runs dist/server.js
```

Also compile the admin panel's TypeScript once (its output, `admin.js`, is
what the browser loads):

```bash
cd admin && npx tsc -p tsconfig.json
```

Visit `http://localhost:5000/admin` and log in with the username/password
from your `.env` file.

## 4. Deploy to Render

1. Push this `portfolio-backend` folder to a GitHub repo.
2. On Render: **New > Web Service**, connect the repo.
3. Build command: `npm install && npm run build && (cd admin && npx tsc -p tsconfig.json)`.
   Start command: `npm start`.
4. Add the same environment variables from your `.env` file in Render's
   **Environment** tab (do not commit `.env` to git).
5. Deploy. Once live, run the seed script once — either locally pointed at the
   Atlas URI, or via Render's Shell tab: `npm run seed`.
6. Your admin panel is now live at `https://<your-service>.onrender.com/admin`.

Note: Render's free tier spins down after inactivity, so the first request
after idle time can take ~30–60 seconds to wake up.

## 5. Connect your portfolio page to this API

In the frontend project's `script.ts`, find:

```ts
const API_BASE: string | null = null;
```

Set it to your deployed API URL, then rebuild (`npm run build` in the
frontend project). The page will then fetch live content on load. If the
API is unreachable, it silently falls back to the hardcoded content already
in the section files — it never breaks.

## API reference

All list resources (`education`, `skills`, `projects`, `experience`,
`certifications`, `achievements`) follow the same pattern:

| Method | Path                        | Auth  | Description          |
|--------|-----------------------------|-------|-----------------------|
| GET    | `/api/<resource>`           | Public | List all, sorted by `order` |
| POST   | `/api/<resource>`           | Admin  | Create new entry      |
| PUT    | `/api/<resource>/:id`       | Admin  | Update an entry       |
| DELETE | `/api/<resource>/:id`       | Admin  | Delete an entry       |

Profile is a single document:

| Method | Path           | Auth  | Description       |
|--------|----------------|-------|--------------------|
| GET    | `/api/profile` | Public | Get profile/about/contact info |
| PUT    | `/api/profile` | Admin  | Update it          |

Auth:

| Method | Path              | Description                    |
|--------|-------------------|---------------------------------|
| POST   | `/api/auth/login` | `{ username, password }` → `{ token }` |

File uploads:

| Method | Path          | Auth  | Description |
|--------|---------------|-------|--------------|
| POST   | `/api/upload` | Admin | Multipart form, field name `file` (max 10MB) → uploads to Cloudinary, returns `{ url }` |

Analytics:

| Method | Path                        | Auth  | Description |
|--------|-----------------------------|-------|--------------|
| POST   | `/api/track`                 | Public | Called by the portfolio page itself to log a pageview or click |
| GET    | `/api/insights/summary`      | Admin  | Unique visitors, total page views, total clicks, active now |
| GET    | `/api/insights/pages`         | Admin  | Most-viewed sections, ranked |
| GET    | `/api/insights/companies`    | Admin  | Visitor organizations, A → Z (best-effort, from IP geolocation) |
| GET    | `/api/insights/locations`    | Admin  | Visitor countries/cities, ranked |
| GET    | `/api/insights/clicks`        | Admin  | Most-clicked links (résumé, project links, contact, etc.), ranked |

The admin panel's **Insights** tab renders all of the above automatically.
Company names come from a free IP-to-organization lookup (ip-api.com, no
key required) — this reliably resolves the real company for corporate or
VPN traffic, but for home internet connections it will just show the ISP
name. It's the closest free approximation of "which company a visitor is
browsing from"; treat it as a signal, not a certainty. No paid reverse-IP
service is used or required.

The admin panel's Education, Projects, and Certifications forms each have an
"Upload" button next to their file field (certificate / project image) that
calls this endpoint automatically and fills in the returned URL — you can
also just paste an external URL directly into that field instead.

Admin routes require `Authorization: Bearer <token>`. The admin panel
handles this automatically once you log in.
